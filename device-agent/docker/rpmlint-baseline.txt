# Known advisory rpmlint findings for sailfish-devagent, one per line, in the normalised form
# `build.sh --docker` prints: the "<package>.<arch>: " prefix removed, e.g.
#   W: no-manual-page-for-binary sailfish-devagent
# `build.sh --docker` fails on any E: line that is not listed here and only reports new W: lines.
# rpmlint is the one mb2 runs after every build (2.0.0 with the SDK's sailfish.toml, which treats
# errors as warnings); the sfdk build prints the same findings. Recorded on 2026-10-07 from the
# 1.9.0 Docker builds; identical for aarch64, armv7hl and i486.
# - non-standard-dir-perm / non-readable / non-standard-uid / non-standard-gid: intended. The
#   settings directory is root:privileged 0770 and settings.json defaultuser:privileged 0660 so
#   that the SSH login cannot change the phone's settings (see the spec and PLAN-settings-page.md).
# - dangerous-command-in-%postun rm: intended, removes the settings directory on uninstall.
# - dangerous-command-in-%post rm (1.10.1): intended, removes only the agent's own
#   `systemctl enable` link in /etc left by agents up to 1.10.0 (the package now ships the link).
# - unstripped-binary / position-independent-executable-suggested / invalid-license /
#   no-changelogname-tag: SDK defaults and the SPDX licence name; harmless.
# - The module packages (agent 1.11.0) add the same unstripped-binary and
#   position-independent-executable findings for their executables in /usr/libexec.
E: no-changelogname-tag
E: non-readable /var/lib/sailfish-devagent/settings.json 660
E: non-standard-dir-perm /var/lib/sailfish-devagent 770
W: dangerous-command-in-%post rm
W: dangerous-command-in-%postun rm
W: invalid-license GPL-3.0-or-later
W: non-standard-gid /var/lib/sailfish-devagent privileged
W: non-standard-gid /var/lib/sailfish-devagent/settings.json privileged
W: non-standard-uid /var/lib/sailfish-devagent/settings.json defaultuser
